1. REQUIREMENTS                                       *ux-chrome-requirements*

Neovim 0.12.2 and UX Foundation schema version 1 are required. Compatibility
with other Neovim releases is not currently claimed. UX Styling is optional;
Chrome registers directly with Foundation and renders normally without the
frontend.

UX Chrome performs presentation work only. It does not invoke Git, GitHub,
network, language-server, or other domain I/O.

==============================================================================
2. INSTALLATION                                       *ux-chrome-installation*

With lazy.nvim: >lua

    {
      "777lotto/UX-foundation.nvim",
      branch = "bluff",
      lazy = false,
    },
    {
      "777lotto/UX-chrome.nvim",
      branch = "bluff",
      dependencies = { "777lotto/UX-foundation.nvim" },
      opts = {},
    }
<
Bluff is the default and only long-lived branch. A signed release tag provides
an immutable version. Installing the plugin does not authorize migration of an
existing live configuration.

3. CONFIGURATION                                             *ux-chrome-config*

Default ownership is auto for every surface: >lua

    require("ux_chrome").setup({
      ownership = {
        tabline = "auto",
        statusline = "auto",
        winbar = "auto",
        statuscolumn = "auto",
        windows = "auto",
        scrollbar = "auto",
      },
    })
<
Valid canonical modes are auto, ux, and external. takeover aliases ux; off
aliases external. Ownership is behavior configuration, not a style-profile
property.

Declared defaults use slanted buffer separators ( and ), a ● modified marker,
powerline status separators ( and ), path breadcrumbs, a relative-number-aware
gutter, fold glyphs, restrained active/inactive treatment, and a lightweight
scrollbar. Number presentation honors native number and relativenumber settings.

setup() validates configuration, initializes the runtime, and registers once.
reset() returns editable presentation values to Chrome's declared defaults. It
does not promise restoration of arbitrary external configuration; teardown()
is the exact physical-restoration boundary.

==============================================================================
4. OWNERSHIP                                                *ux-chrome-ownership*

auto       Acquire an available native surface and preserve an existing
           external expression.
ux         Explicitly select UX Chrome as physical owner.
external   Register declarations and fixtures without taking the surface.

During M3 the current configuration retains Bufferline and Lualine. Use
external for tabline and statusline in isolated coexistence tests, and do not
migrate the live nvim-config. Chrome claims only UXChrome* highlight names and
component-scoped keys through the ux_chrome adapter, so M2 compatibility
registrations can coexist.

M4 must disable the corresponding third-party implementation and Styling
adapter before switching one surface to ux. Keep the prior plugin available
until parity and rollback pass. See docs/ownership-switch.md.

5. COMMANDS                                                  *ux-chrome-commands*

:UXChromeEnable[!] [surface]
        Enable all surfaces or one surface. Bang requests explicit UX ownership.

:UXChromeDisable [surface]
        Disable all surfaces or one surface.

:UXChromeToggle[!] [surface]
        Toggle all surfaces or one surface. Bang requests UX ownership when
        enabling.

:UXChromeRefresh
        Atomically reconcile and redraw owned surfaces.

:UXChromeReset
        Reset Chrome presentation properties to declared defaults.

:UXChromeDebug
        Show a defensive runtime and ownership snapshot.

:UXChromeHealth
        Run UX Chrome health checks.

:UXChromeBufferNext       Select the next displayed buffer.
:UXChromeBufferPrev       Select the previous displayed buffer.
:UXChromeBufferFirst      Select the first displayed buffer.
:UXChromeBufferLast       Select the last displayed buffer.
:UXChromeBufferClose      Close the current displayed buffer safely.
:UXChromeBufferMoveLeft   Move the current buffer left in presentation order.
:UXChromeBufferMoveRight  Move the current buffer right in presentation order.

No default mappings are installed.

6. LUA API                                                        *ux-chrome-api*

The module is returned by: >lua

    local chrome = require("ux_chrome")

    chrome.setup(opts)
    chrome.refresh()
    chrome.reset()
    chrome.teardown()
    chrome.enable(surface, force)
    chrome.disable(surface)
    chrome.toggle(surface, force)
    chrome.state()
    chrome.debug()
    chrome.manifest()
    chrome.fixtures()

    chrome.tabline()
    chrome.statusline()
    chrome.winbar()
    chrome.statuscolumn()
    chrome.foldtext()

    chrome.select_buffer(which)
    chrome.move_buffer(delta)
    chrome.close_buffer()
    chrome.health()
<
The surface argument is optional. Omitting it applies enable, disable, or toggle
to all configured surfaces. manifest(), fixtures(), state(), and debug() return
defensive data without executable callbacks.

refresh() atomically reconciles physical ownership. teardown() removes
lifecycle hooks, closes scrollbar resources, unregisters from Foundation, and
restores acquired global and window-local options exactly.

The five renderer functions are native option-expression entry points. They read
bounded current Neovim state and never perform blocking or external I/O. The
optional force argument selects explicit ux ownership when enabling.

7. RENDERING                                                  *ux-chrome-render*

Shared plugin navigation uses require("ux_chrome.components").context({id,
window, width, redraw}). Its format({kind, text, prefix, count, depth}) method
returns one line and a byte-indexed highlight span. Kinds are row, header,
and empty. Plugins retain their action targets and application behavior.

Foundation exposes padding, indent, gap, and truncation at
ux.chrome.components/navigation/<setting>/value. Per-component overrides use
ux.chrome.component.<id>/navigation/<setting>/value; -1 and "inherit" inherit
numeric and truncation settings respectively. A redraw callback must rebuild
presentation synchronously from cached content. Window closure releases it.
See docs/components.md for the complete contract and lifecycle requirements.

The tabline shows listed buffers with active, visible, inactive, modified,
overflow, empty, and native-tab-page states. The statusline shows mode,
filename, modified/read-only state, encoding, file format, filetype, progress,
and ruler, dropping lower-priority items at narrow widths. The winbar renders
path breadcrumbs. The statuscolumn composes folds, signs, relative/absolute
numbers, and a separator. Fold text is deterministic and includes line count.

The scrollbar is a lightweight presentation rail. It does not parse source into
a semantic minimap. Render callbacks use bounded current state and no domain I/O.

Chrome separates ownership reconciliation from redraw. Reconciliation is the
only path that reads or writes a managed option, and it runs solely on events
that can change ownership or window and buffer topology: BufAdd, BufDelete,
DirChanged, TabClosed, TabEnter, TabNewEntered, VimResized, WinClosed,
WinEnter, WinLeave, WinNew, ColorScheme, Foundation lifecycle events, and
OptionSet on an option Chrome manages.

High-frequency editing events never reconcile. Neovim re-evaluates the
'statusline', 'winbar' and 'statuscolumn' expressions on its own redraw, so
CursorMoved, CursorMovedI, ModeChanged, TextChanged, TextChangedI,
TextChangedP, TextChangedT and WinScrolled take a cheap path that only follows
scrollbar geometry. BufEnter, BufModifiedSet and BufWritePost additionally
request a tabline redraw, which Neovim does not perform on its own.

OptionSet raised by Chrome's own writes is ignored while a reconciliation is in
progress, so a reconcile cannot schedule a second reconcile of its own echo.

All managed groups are prefixed UXChrome. Chrome never claims BufferLine* or
lualine_* names.

8. HEALTH AND DEBUGGING                                      *ux-chrome-health*

Run: >vim

    :checkhealth ux_chrome
    :UXChromeHealth
    :UXChromeDebug
<
Health reports Neovim and Foundation availability, schema version,
registration, surface ownership, and restoration capability. Debug output is a
defensive snapshot and contains no executable callbacks.

==============================================================================
9. DEVELOPMENT                                          *ux-chrome-development*

CI and local gates use Neovim 0.12.2. Tests isolate XDG config, data, state,
cache, runtimepath, and plugin loading and never load the live configuration.
The named suites are unit, render, smoke, foundation_integration, and
styling_integration. Catalog metadata declares 100-, 72-, and 40-column layouts;
renderer tests also exercise narrower pathological bounds.

Development branches start from and return to bluff. Signed tags and GitHub
Releases mark verified bluff commits. Keep the Foundation schema-v1 contract
frozen unless a concrete failing fixture requires a reviewed compatible
change.

10. OUTPUT DRAWER                                           *ux-chrome-drawer*

Click Logs in Chrome's statusline or run :UXChromeDrawerToggle. The full-width
bottom split remembers its height and selected source per tab. Drag its upper
divider to resize it. Background updates preserve focus; scrolling back pauses
following. Unread counts cover retained lines; !N counts unread error lines.
The Messages source snapshots :messages when opened or explicitly refreshed.

Commands: >vim

    :UXChromeDrawerOpen[!] [provider.id]
    :UXChromeDrawerToggle
    :UXChromeDrawerClose
    :UXChromeDrawerSource
    :UXChromeDrawerFollow
    :UXChromeDrawerFilter [text]
    :UXChromeDrawerRefresh
    :UXChromeDrawerClear
<
Open with ! preserves focus. Empty filter text resets the filter. Buffer-local
keys: s selects, f follows/pauses, F filters, r refreshes, C clears, q closes.
Normal search and copying remain available. No global keys are installed.

Providers register once and supply cached text: >lua

    local drawer = require("ux_chrome.drawer")
    drawer.register({ id = "example.build.output", label = "Build", limit = 5000 })
    drawer.append("example.build.output", "Started")
    drawer.append("example.build.output", { text = "Failed", level = "error" })
    drawer.open("example.build.output", { focus = false })
<
append/replace accept a string, a {text, level} entry, or a list of these.
Levels: debug, info, warn, error. The line limit is 1-50000 (default 5000).
Optional refresh() returns a replacement snapshot or nil for asynchronous work;
optional clear() runs before clearing. Callbacks run only on explicit actions.
Duplicate IDs raise an error. unregister(id) removes the source; teardown()
closes all drawers. chrome.teardown() includes drawer cleanup.

status([tabpage]) returns cached unread/errors/open values; inspect([tabpage])
returns defensive session state. providers() lists IDs, labels, and line counts.
follow([boolean]), filter(text), refresh([id]), clear(), open([id], [opts]),
close(), toggle(), and choose() are also available. See docs/drawer.md for the
provider contract and lifecycle details. This API is independent of editor-bar
ownership and reuses the shared log pane presentation.
